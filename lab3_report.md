## 2. Теоретическая часть

### 2.1. Структура файла `/etc/passwd`
Каждая учетная запись в Linux представлена отдельной строкой в файле `/etc/passwd`. Строка состоит из 7 полей, разделенных двоеточием (`:`):
1. **Логин (Login):** Уникальное имя учетной записи.
2. **Флаг пароля:** Символ `x` указывает, что зашифрованный пароль хранится отдельно в `/etc/shadow`.
3. **UID (User ID):** Цифровой идентификатор пользователя.
4. **GID (Group ID):** Цифровой идентификатор основной группы пользователя.
5. **GECOS (Комментарий):** Дополнительная информация (например, ФИО, номер группы).
6. **Домашняя папка (Home directory):** Рабочий каталог, куда пользователь попадает при входе.
7. **Командная оболочка (Shell):** Интерпретатор команд, запускаемый для сессии пользователя.

### 2.2. Понятие системных (Non-login) пользователей
Некоторые учетные записи создаются исключительно для работы демонов и служб (например, `nginx`, `mysql`). В целях безопасности им закрыт интерактивный вход в консоль с помощью установки специальной командной оболочки-заглушки:
* `/usr/sbin/nologin` (выводит вежливое сообщение и разрывает сессию)
* `/bin/false` (завершает процесс с кодом ошибки без вывода сообщений)

## 3. Практическая часть

### 3.1. Управление учетными записями

#### Создание пользователя
Была выполнена команда создания нового пользователя с полной конфигурацией параметров:
```bash
sudo useradd -m -s /bin/bash -c "Иванов Иван Иванович" -G sudo,users ivanov
```
*Разбор флагов:*
* `-m` — создать домашний каталог `/home/ivanov`
* `-s /bin/bash` — принудительно назначить оболочку Bash
* `-c` — задать комментарий GECOS
* `-G sudo,users` — добавить в дополнительные группы для выдачи прав администратора

Для установки пароля использовалась утилита:
```bash
sudo passwd ivanov
```

#### Изменение командного интерпретатора (Способ 1 и Способ 2)
1. **Через системную утилиту:**
   ```bash
   sudo chsh -s /bin/zsh ivanov
   ```
2. **Через прямое безопасное редактирование файла конфигурации:**
   ```bash
   sudo vipw
   ```
   *Результат:* Оболочка была отредактирована непосредственно внутри открывшегося редактора `nano`. Проверка корректности внесения изменений выполнена командой:
   ```bash
   grep ivanov /etc/passwd
   ```

#### Установка non-login shell
Была протестирована блокировка интерактивного входа для сервисного аккаунта:
```bash
sudo useradd -m service_user
sudo usermod -s /usr/sbin/nologin service_user
```
При попытке выполнения `sudo su - service_user` система мгновенно прерывает сессию, подтверждая успешность блокировки.

#### Удаление пользователей
Отработаны механизмы удаления учетных записей:
1. Простая очистка записи: `sudo userdel service_user` (файлы остаются).
2. Полное удаление с домашней директорией: `sudo userdel -r ivanov` (очистка дискового пространства).

### 3.2. Управление правами доступа к файлам и каталогам

#### Изменение владельцев (`chown`)
Создан тестовый файл `document.txt`, после чего права владения переданы пользователю `ivanov` и его группе:
```bash
touch document.txt
sudo chown ivanov:ivanov document.txt
```
Проведена рекурсивная смена владельца на целую ветку каталогов:
```bash
sudo mkdir -p /var/www/project/
sudo chown -R ivanov:users /var/www/project/
```

#### Изменение разрешений (`chmod`)
Были отработаны числовые маски назначения прав доступа:
1. Исполняемый файл для всех (`755`): `chmod 755 script.sh` (вывод `ls -l` -> `-rwxr-xr-x`)
2. Стандартный документ (`644`): `chmod 644 config.ini` (вывод `ls -l` -> `-rw-r--r--`)
3. Защищенный приватный каталог (`700`): `sudo chmod 700 /home/ivanov/.ssh/` (вывод `ls -ld` -> `drwx------`)

Также изучено рекурсивное изменение разрешений для папок:
```bash
chmod -R 700 test_dir
```

#### Использование специальных битов
Изучен механизм работы дополнительных флагов безопасности:
* **SUID (`u+s`):** Запуск исполняемого файла с привилегиями его владельца. Был проанализирован предустановленный флаг на утилите смены паролей: `ls -l /usr/bin/passwd` (флаг `-rwsr-xr-x`).
* **SGID (`g+s`):** Наследование вложенными объектами группы родительской папки. Выполнена команда: `sudo chmod g+s /shared/directory`.
* **Sticky bit (`+t`):** Запрет на удаление чужих файлов в общих каталогах. Проанализирована папка временных файлов: `ls -ld /tmp` (флаг `drwxrwxrwt`).

### 3.3. Персонализация среды

#### Конфигурация `.bashrc`
В конец файла `~/.bashrc` добавлены настройки истории команд и полезные псевдонимы (алиасы):
```bash
export HISTSIZE=5000
export HISTTIMEFORMAT="%d/%m/%y %T "
export HISTCONTROL=ignoreboth

alias ll='ls -alF --color=auto'
alias ..='cd ..'
```
Для мгновенного применения конфигурации без перезапуска терминала выполнена команда: `source ~/.bashrc`.

#### Кастомизация Vim и плагины
Создан файл персональных настроек редактора `~/.vimrc`, куда внесены базовые параметры:
```text
set number
syntax on
colorscheme desert
set mouse=a
set autoindent
set tabstop=4
set encoding=utf-8
```

В рамках изучения автоматизированного менеджмента плагинов была рассмотрена интеграция инструмента **Vundle**. Команда ручного скачивания с удаленного репозитория:
```bash
git clone https://github.com/VundleVim/Vundle.vim.git ~/.vim/bundle/Vundle.vim
```
*Примечание:* Из-за изоляции локальной конфигурации сети (отсутствие связи виртуалки с внешним DNS-сервером) произошла штатная ошибка разрешения хоста `fatal: Could not resolve host: github.com`. В штатном режиме данная операция подготавливает среду для пакетной интеграции расширений (таких как файловый менеджер `nerdtree`) через внутренний интерфейс Vim по команде `:PluginInstall`.
