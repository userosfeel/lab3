## 1. Теоретическая справка (Как всё устроено под капотом)

### Структура файла /etc/passwd
Каждая учетка в Linux занимает ровно одну строку в файле `/etc/passwd`. Строка состоит из 7 полей, разделенных двоеточиями:
1. Имя (логин): Уникальное имя для входа в систему.
2. Пароль: Здесь стоит символ `x`, который означает, что сам зашифрованный пароль надежно спрятан в другом файле — `/etc/shadow`.
3. UID: Номер пользователя (цифровой ID, по которому ядро Linux отличает людей).
4. GID: Номер основной группы, к которой привязан пользователь.
5. GECOS: Комментарий, куда обычно записывают настоящее имя (ФИО) или группу.
6. Домашняя папка: Личный каталог пользователя, куда он попадает сразу после входа.
7. Оболочка (shell): Программа (интерпретатор команд), которая запускается при открытии терминала.

### Системные (non-login) пользователи
В Linux учетные записи нужны не только живым людям, но и фоновым программам (например, веб-серверам). В целях безопасности им запрещено интерактивно заходить в систему. У них в конце строки вместо стандартной командной строки прописана заглушка `/usr/sbin/nologin`. Если кто-то попытается авторизоваться под ними, система просто сбросит соединение.

## 2. Практическая часть

### Пункт 2.1. Управление учетными записями
Для экспериментов я сначала добавил в систему обычного пользователя:
```bash
sudo useradd -m -s /bin/bash -c "Иванов Иван Иванович" -G sudo ivanov
```
Эта команда создала учетную запись `ivanov`, автоматически выделила ему домашнюю папку (`-m`), назначила удобный интерпретатор `bash` (`-s`), заполнила ФИО (`-c`) и выдала права администратора через группу `sudo` (`-G`).

Далее я протестировал два способа изменения командной оболочки:
1. Через утилиту `chsh`: Выполнил команду `sudo chsh -s /bin/zsh ivanov`. Она безопасна и меняет только одно конкретное поле.
2. Вручную через `vipw`: Открыл файл `/etc/passwd` с помощью команды `sudo vipw`. Редактор открылся через удобный `nano` (я выбрал его в меню по цифре 1). Переместил курсор в самый конец строки пользователя, удалил старый путь и вручную вписал новый. Это позволило отредактировать конфигурацию напрямую, при этом утилита проверила синтаксис на ошибки перед сохранением.

[ЗДЕСЬ СКРИНШОТ: Вывод команды `grep ivanov /etc/passwd` после редактирования файла, где в самом конце строки видно измененный shell].

### Установка non-login shell (Пункт 2.1.4)
Я создал тестового пользователя `service_user` и заблокировал ему доступ в консоль:
```bash
sudo usermod -s /usr/sbin/nologin service_user
```
Для проверки я попытался войти под ним через команду `su - service_user`. Поскольку у созданного пользователя по умолчанию нет пароля, система сразу выдала ошибку проверки подлинности.

[ЗДЕСЬ СКРИНШОТ: Ошибка «su: Сбой при проверке подлинности» при попытке войти в заблокированный аккаунт].

### Удаление пользователей (Пункт 2.1.5)
Я проверил, как работают разные варианты удаления учетных записей:
* `sudo userdel service_user` — простое удаление. Сам аккаунт исчез из системы, но его файлы остались на жестком диске.
* `sudo userdel -r ivanov` — полное удаление. Система начисто стерла и самого пользователя, и его личный домашний каталог `/home/ivanov`. При этом на экране появилось предупреждение, что почтовый ящик `/var/mail/ivanov` не найден — это нормально, так как почтой этот пользователь не пользовался.

[ЗДЕСЬ СКРИНШОТ: Экран терминала с процессом выполнения команды `sudo userdel -r ivanov` и системным предупреждением о почтовом ящике].

### Пункт 2.2. Управление правами доступа к файлам

Для проведения тестов я создал файлы `script.sh`, `config.ini` и папку `/home/ivanov/.ssh/`. Далее я настроил владельцев с помощью команды `chown` и выставил точные уровни доступа через числовую нотацию команды `chmod`:

1. `chmod 755 script.sh` — сделал файл исполняемым скриптом. Владелец может делать всё, остальные — только читать и запускать.
2. `chmod 644 config.ini` — стандартные права для обычных документов. Мне можно изменять, всем остальным — только смотреть.
3. `sudo chmod 700 /home/ivanov/.ssh/` — жестко защитил личную папку с ключами доступа. Все права выданы исключительно владельцу папки, для всех остальных пользователей системы она полностью закрыта. Использовал `sudo`, так как папка принадлежит другому пользователю.

[ЗДЕСЬ СКРИНШОТ: Вывод команды `ls -l script.sh config.ini` и `sudo ls -ld /home/ivanov/.ssh/`, где наглядно видны права `-rwxr-xr-x`, `-rw-r--r--` и `drwx------`].

Также я разобрался с рекурсивным изменением (`-R`). Если применить `chmod -R` или `chown -R` к какой-то папке, то команда автоматически «спустится» по всему дереву каталогов и за секунду поменяет права и владельцев для всех вложенных файлов и подпапок (например: `sudo chown -R ivanov:users /var/www/project/`).

### Специальные биты (Пункт 2.2.3)
Я разобрал, зачем нужны три скрытых бита автоматизации и безопасности в Linux:
* SUID (`u+s`): Запуск программы с правами её владельца (администратора). Отличный пример — утилита `/usr/bin/passwd`. Обычный человек запускает её и временно получает права `root`, чтобы обновить свой скрытый пароль в системе. В выводе `ls -l` этот бит заметен по букве `s` на месте прав владельца.
* SGID (`g+s`): Наследование группы. Я проверил это на созданной папке: `sudo chmod g+s /shared/directory`. Теперь любой файл, который кто-то создаст внутри этой папки, автоматически получит группу `directory`. Это удобно для совместной командной работы.
* Sticky bit (`+t`): Защита от удаления чужих файлов. По умолчанию активен в общей временной папке `ls -ld /tmp` (обозначается буквой `t` в самом конце строки прав). Любой пользователь может создавать там файлы, но удалить чужой документ ему запрещено — стирать файлы может только их автор.

### Пункт 2.3. Персонализация консоли через .bashrc
Чтобы сделать работу в терминале более удобной и быстрой, я открыл личный файл настроек `nano ~/.bashrc` и дописал в самый конец минимальный, но самый эффективный набор опций:

1. Красивый цветной интерфейс со временем:
```bash
export PS1="\[\e[36m\][\t]\[\e[m\] \[\e[32m\]\u@\h\[\e[m\]:\[\e[33m\]\w\[\e[m\]\n\$ "
```
2. Короткие сокращения (алиасы) для повседневных команд:
```bash
alias ll='ls -alF --color=auto'
alias ..='cd ..'
alias update='sudo apt update && sudo apt upgrade'
```
3. Настройки истории команд:
```bash
export HISTSIZE=5000
export HISTTIMEFORMAT="%d/%m/%y %T "
export HISTCONTROL=ignoreboth
```
Чтобы применить изменения без перезагрузки компьютера, я выполнил команду `source ~/.bashrc`. Терминал мгновенно стал цветным и аккуратным, а сокращения начали работать.

[ЗДЕСЬ СКРИНШОТ: Преобразившийся цветной экран терминала с отображением текущего времени и результатом работы введенного алиаса `ll`].

### Пункт 2.4. Прокачка текстового редактора Vim и плагины
Для базовой настройки внешнего вида Vim я создал файл конфигурации `nano ~/.vimrc` и добавил туда 7 самых критически важных строк, чтобы редактор стал дружелюбным к пользователю:
```text
set number
syntax on
colorscheme desert
set mouse=a
set autoindent
set tabstop=4
set encoding=utf-8
```
После этого в Vim заработала подсветка синтаксиса, пронумеровались строчки и появилась поддержка мыши (можно кликать по тексту и крутить колесико).

#### Менеджер плагинов Vundle (Пункт 2.4.3)
Далее по заданию требовалось установить плагины (расширения, которые работают как приложения на телефоне, добавляя новые крутые фичи — вроде бокового дерева файлов `nerdtree`).

При попытке скачать менеджер Vundle с помощью команды:
```bash
git clone https://github.com ~/.vim/bundle/Vundle.vim
```
Я столкнулся с системной ошибкой: `fatal: Could not resolve host: github.com`.

**Причина ошибки:** Данная сетевая ошибка возникла из-за того, что моя виртуальная машина изолирована от внешней сети интернет (работает в закрытом локальном режиме Host-only). В условиях реального интернет-соединения эта команда автоматически скачивает все скрипты менеджера плагинов Vundle в скрытую директорию `~/.vim/bundle/`, после чего внутри Vim через встроенную команду `:PluginInstall` разворачиваются любые нужные дополнения.
